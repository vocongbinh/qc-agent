# Code Intelligence Graph Guide for QC Agent

## 1. Overview
QC Agent includes a built-in static analysis and code intelligence subsystem combining **Tree-sitter**, **SCIP (Source Code Intelligence Protocol)**, and **KùzuDB** (embedded property graph database).

It enables QC Agent to:
- Retrieve functions, execution branches, and call dependencies scoped to specific files or packages.
- Prioritize complex functions based on **Cyclomatic Complexity** and branch counts.
- Generate high-coverage test cases without bloating LLM context windows or reading full repository source codes.
- Trace shortest execution call chains for root-cause fault localization.

## 2. Architecture & Design Principles

```text
Target Codebase (Go)
   │
   ├──> [1. scip-go] ───────> index.scip (Definitions & References)
   │
   └──> [2. Tree-sitter] ───> AST analysis:
                                - Function coordinates: start_line, end_line, start_byte, end_byte
                                - Metrics: cyclomatic_complexity, branch_count
   │
   ▼
[3. Indexer & Stitcher]
   - Nodes: File, Function, StructOrClass, Endpoint
   - Relationships: CONTAINS, CALLS (stitched via byte/line spans)
   - Database: KùzuDB (.codeintel_db)
   │
   ▼
[4. Agent Query Tools (Read-Only)]
   - inspect_function_branches (JIT slice parsing via Tree-sitter)
   - get_external_dependencies
   - trace_execution_path (Cypher shortest path)
   - get_function_source (bounded, path-confined)
   - list_scope_functions
```

### Key Decisions
1. **No Free-form Cypher:** LLMs only invoke parameter-locked tools returning structured JSON (`{"ok": bool, "data": Any, "error": str | None}`).
2. **Thin Graph + JIT Leaf Extraction:** Branch conditions are NOT stored as separate nodes in KùzuDB (preventing combinatorial explosion). Instead, branch details are parsed on-demand via Tree-sitter from disk slices.
3. **Read/Write Separation:**
   - **Write Phase:** Standalone batch CLI `main.py index` uses writer mode (`read_only=False`) and releases file locks on exit.
   - **Read Phase:** LangGraph worker threads connect using thread-safe singleton reader connections (`read_only=True`), completely avoiding file lock conflicts.

## 3. Usage & CLI

### 3.1 Building the Code Index
To index a repository:

```bash
python main.py index --root /path/to/my_go_repo --lang go
```

Options:
- `--root`, `-r`: Target repository path (default: current directory).
- `--lang`, `-l`: Programming language (Phase 1 supports `go`).
- `--db`, `-d`: Optional custom output directory for KùzuDB (default: `.codeintel_db`).

Output:
- Creates `.codeintel_db/` embedded database.
- Writes `.codeintel_db/index_stats.json` with file, function, and call counts.

### 3.2 Enabling in QC Agent
In your `.env` file or environment settings:

```env
ENABLE_CODEINTEL=true
```

When enabled, LangGraph runs the `codeintel_retriever` node prior to `planner`, injecting high-complexity function structures, branches, and dependencies directly into the planning context.

If `ENABLE_CODEINTEL=false` or if the database does not exist, the retriever cleanly passes through with zero overhead.

## 4. Agent Tools Reference

All tools reside in `codeintel/tools/` and adhere to the JSON envelope:

```json
{
  "ok": true,
  "data": { ... },
  "error": null
}
```

### 4.1 `inspect_function_branches(func_id, repo_root=".")`
Fetches byte coordinates from KùzuDB, seeks the exact function slice on disk, and extracts all decision branches (e.g. `if`, `for`, `case`, `&&`, `||`) with accurate file line offsets.

### 4.2 `get_external_dependencies(func_id)`
Returns all outgoing `CALLS` relations from the target function, including target function name, line number, and `is_external` classification.

### 4.3 `trace_execution_path(source_func_id, sink_func_id)`
Executes Cypher shortest-path queries (`MATCH p = (src)-[:CALLS* SHORTEST 1..10]->(sink)`) between an entry point and a target or failing function.

### 4.4 `get_function_source(func_id, max_lines=150, repo_root=".")`
Reads the exact line span for the function from disk with path traversal protection (confined within `repo_root`) and auto-truncation if length exceeds `max_lines`.

### 4.5 `list_scope_functions(package="", min_complexity=1)`
Lists functions ordered by `cyclomatic_complexity DESC` with optional package filtering, helping the agent prioritize high-risk functions for test planning.

## 5. Phase 1 Scope & Limitations
- **Supported Languages:** Go (`*.go`).
- **Compiler Requirements:** If an `index.scip` file generated by `scip-go` is present in the repository root, call relationships achieve 100% semantic compiler resolution. If absent, the indexer falls back cleanly to Tree-sitter AST symbol resolution.
- **Excluded Paths:** `.git`, `.venv`, `vendor`, and `node_modules` are automatically skipped during indexing.
